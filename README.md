# Invitación de Baby Shower – Samuel

Sitio estático para la invitación digital con diseño emocional y moderna.

## Funcionamiento general

- **Frontend estático:** `index.html`, `styles.css` y `script.js`. No hay backend propio ni Google Sheets.
- **Backend de datos:** Supabase (PostgreSQL + funciones RPC). La conexión se configura en `script.js`:

  ```javascript
  const SUPABASE_URL = 'https://echlxupvtvfuxomahydh.supabase.co';
  const SUPABASE_ANON_KEY = 'sb_publishable_...';
  ```

- **Invitaciones personalizadas:** cada invitado tiene un `token` único y recibe una URL del tipo `https://TU-SITIO/?i=TOKEN`.
- **RSVP:** la respuesta se guarda de forma atómica con `register_guest_rsvp`, que evita duplicados.

Al abrir el sitio, `script.js`:

1. Lee el parámetro `i` de la URL.
2. Consulta `get_guest_by_token` para validar el token y obtener `name`, `max_guests` y `active`.
3. Verifica con `has_guest_responded` si la invitación ya fue respondida.
4. Muestra el formulario y guarda la respuesta con `register_guest_rsvp`.

Sin parámetro `i` (o con un token inválido/inactivo) no se muestra el formulario, solo un aviso.

## Requisitos previos antes de generar las URLs

1. **Proyecto de Supabase** con la URL y la clave pública configuradas en `script.js`.
2. **Tablas** `public.guests` y `public.rsvp`.
3. **Funciones RPC** en Supabase: `get_guest_by_token`, `has_guest_responded` y `register_guest_rsvp`.
4. Ejecutar una sola vez [`supabase-rsvp-guards.sql`](./supabase-rsvp-guards.sql) en el *SQL Editor* de Supabase (crea `has_guest_responded` y `register_guest_rsvp`).
5. **Publicar el sitio** (GitHub Pages, Netlify, Vercel, etc.) para tener la URL base del dominio.

### Esquema de datos

`public.guests`:

| Columna | Descripción |
| --- | --- |
| `id` | Identificador del invitado. |
| `name` | Nombre que se muestra al invitado. |
| `token` | Código único que va en la URL. |
| `max_guests` | Personas de la invitación (`1` = solo el invitado, `2` = invitado + 1 acompañante). |
| `active` | `true` si la invitación está disponible; `false` la desactiva. |

`public.rsvp`: `guest_id`, `guest_name`, `attendance` (`yes`/`no`), `with_companion` (`yes`/`no`), `companion_name`.

Si las tablas todavía no existen, puedes crearlas con:

```sql
create table if not exists public.guests (
  id bigint generated by default as identity primary key,
  name text not null,
  token text not null unique,
  max_guests integer not null default 1 check (max_guests >= 1),
  active boolean not null default true
);

create table if not exists public.rsvp (
  id bigint generated by default as identity primary key,
  guest_id bigint references public.guests(id) on delete set null,
  guest_name text,
  attendance text not null check (attendance in ('yes','no')),
  with_companion text not null default 'no',
  companion_name text not null default '',
  created_at timestamptz not null default now()
);
```

La función `get_guest_by_token` debe devolver `id`, `name` y `max_guests`, y devolver vacío cuando el invitado no existe o está inactivo (`active = false`). Ejemplo si aún no existe:

```sql
create or replace function public.get_guest_by_token(p_token text)
returns table (id bigint, name text, max_guests integer)
language sql
security definer
set search_path = public
as $$
  select g.id, g.name, g.max_guests
  from public.guests g
  where g.token = p_token
    and g.active = true
  limit 1;
$$;

revoke all on function public.get_guest_by_token(text) from public;
grant execute on function public.get_guest_by_token(text) to anon;
```

## Cómo se generan las URLs personalizadas

La URL personalizada es la URL base del sitio publicado más el parámetro `i` con el token del invitado:

```text
https://TU-SITIO/?i=TOKEN
```

El token se guarda en `guests.token`. Crea cada invitado generando un token aleatorio:

```sql
insert into public.guests (name, token, max_guests, active)
values (
  'María López',
  encode(gen_random_bytes(8), 'hex'),
  2,     -- 1 = solo el invitado, 2 = invitado + 1 acompañante
  true
)
returning name, token;
```

Con el valor devuelto en `token`, arma el enlace:

```text
https://TU-SITIO/?i=9f2c1ab34d5e6f70
```

Para obtener todas las URLs listas para enviar:

```sql
select
  name,
  token,
  max_guests,
  active,
  'https://TU-SITIO/?i=' || token as url
from public.guests
order by name;
```

Para desactivar una invitación (su enlace deja de ser válido):

```sql
update public.guests
set active = false
where token = 'TOKEN';
```

> Trata el token como una contraseña: usa cadenas largas y aleatorias y no las reutilices.

## Cómo funciona el formulario RSVP

- **Token válido y `active = true`** → se muestra el formulario.
- **`max_guests = 2`** → se habilita la opción de acompañante (máximo 2 personas). Con `max_guests = 1` solo se registra al invitado.
- **`has_guest_responded` devuelve `true`** → se oculta el formulario y se avisa que la respuesta ya fue registrada.
- **Al enviar**, `register_guest_rsvp` registra la respuesta de forma atómica y devuelve `registered`, `already_responded` o `invalid_invitation`.

La lógica de las funciones está en [`supabase-rsvp-guards.sql`](./supabase-rsvp-guards.sql) y en el *SQL Editor* del proyecto Supabase.
